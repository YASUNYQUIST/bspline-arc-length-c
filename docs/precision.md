# 精度验证、判据与实测结果

## 1. 验证方法

本项目分三层验证，避免 C 和 Python 同时复制同一错误却仍互相通过：

1. **C 解析测试**：四次共线 Bezier `C(u)=(3u,4u)` 的总长为 5；重复控制点构成的 `C(u)=(u⁴,0)` 的累计弧长为 `u⁴`，包含零速度起点；还检查常值曲线、端点、不可达目标、非法输入、点数限制和搜索未收敛。
2. **Python 公式对照**：使用用户提供算法整理的 `python/reference.py`，对照几何控制点、节点、de Boor 坐标、导数、误差搜索和实际生效的 Newton + 二分反求。保留原圆周方向和分母阈值。
3. **独立数值参考**：用 SciPy `BSpline` 和其导数独立检查求值；按节点拆分后用 QUADPACK 自适应积分计算参考弧长；用 Brent 求根独立检查反求参数。另用 200001 点梯形积分复现原脚本的密集检查，并对几何误差作同等密度审计。

每组输入对照 257 个参数处的坐标、导数和累计弧长；从四个不同起始参数各反求三种目标长度，共 12 次。此外每组都对照原示例 `u0=0.5, L=1.2`。12 组共包含 144 次多起点反求，另有 12 次原示例反求。

第三层依然是高精度数值参考，不是区间算术证明。所有数字以报告中的输入、环境和容差为准。

## 2. 输入覆盖

| 测试 | 目的 |
|---|---|
| `original-input` | 原始 A、O、R、branch 和误差区间 |
| `opposite-branch` | 另一切点分支 |
| `translated` | 坐标平移 |
| `rotated` | 坐标旋转 0.73 弧度 |
| `scale-0.1`, `scale-10.0` | 几何与误差阈值同比例缩放 |
| `continuous--1`, `continuous-1` | 修正切向方向的两个分支 |
| `seeded-0`～`seeded-3` | NumPy 种子 20261029 的随机几何 |

随机用例覆盖不同半径、圆心和外点距离，全部具体输入保存在 [precision_report.json](precision_report.json)。`--continuous` 会改变算法路径，必须与同样启用该选项的 Python 比较。

## 4. 判据及容差

令 `scale=max(1,R/150)`。自动对照采用绝对容差，防止仅用相对误差掩盖接近零的数值偏差。

| 检查项 | 允许绝对误差 |
|---|---:|
| `d` | `1e-12*scale` |
| 控制点 | `1e-9*scale` |
| 节点 | `5e-13` |
| 1000 点最大几何误差 | `1e-9*scale` |
| 曲线坐标 | `2e-9*scale` |
| 导数 | `2e-6*scale` |
| 总长、累计长度对独立积分 | `1e-8*scale` |
| 默认反求点、长度对原 Python | `3e-6*scale` |
| 默认反求独立弧长残差 | `1.01e-6` |
| 多起点反求独立弧长残差 | `1.1e-8*scale` |
| 多起点反求参数对 Brent | `1e-9` |

示例为共享弧长对象设置 `1e-10` 积分容差，明显小于 `1e-6` 默认反求目标容差。额外多起点测试的反求目标容差设为 `1e-8`。

这些判据用于回归验证，不代表在任意坐标尺度、任意退化输入上都有同样精度。极大坐标、极短距离、大前缀相减、极密节点和多次相减可能导致精度损失；应按目标应用的单位和尺度重新测试。

## 5. 为什么 C 的弧长不与原 Python 逐位相同

原 Python 使用 `n` 与 `2n` 积分之差作为局部误差估计，但达到 `n_max` 后无条件接受结果，不管误差判据是否满足。因此“总误差小于 err”的原注释过强。

原始输入中：

- 原 Python 的实际弧长误差约 `1.09e-7`。
- 原 Python 报告的各段两阶差之和约 `7.78e-6`，已大于请求的 `1e-6`。
- 十倍缩放输入中，原 Python 的实际弧长误差约 `1.09e-6`，超过其 `1e-6` 请求。

C 在阶数到达上限时细分区间，默认输入与独立参考总长相差约 `4.55e-13`。这保留了同一条样条曲线，同时避免复制原积分的达限误差。

另外，200001 点的梯形参考在默认输入上与独立积分仍差约 `1.53e-6`；因此不能把密集梯形结果当作精确真值，尤其不能据此声称 C 版只有 `1e-6` 精度。

## 6. 采样最大值与真实最大值

原始输入在 1000 个均匀参数点上得到 `0.043996841487683014`；200001 点审计得到约 `0.04399751743221714`。两者都落在 `[0.04,0.05]` 内，但不完全相同。

本次 12 组的密集几何误差审计也都落在各自的目标区间内，验证脚本会检查密集最大值不超过上限。密集审计仍然只是更细的采样，不构成对连续参数域的严格最大值证明。

若需要严格几何误差保证，还需加入逐节点区间的误差极值搜索、可证明上界或区间算术，并明确误差对象是否仍是“无限直线与整圆的并集”。当前实现没有把采样误差包装成这种保证。

## 7. 重现命令

在项目根目录执行：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
python3 -m pip install -r requirements-test.txt
python3 python/verify.py --exe build/bspline_demo --report docs/precision_report.json

cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug -DBSPLINE_SANITIZE=ON
cmake --build build-sanitize -j 4
ctest --test-dir build-sanitize --output-on-failure
```

本地 Release 的 C 测试、12 组跨语言对照以及 AddressSanitizer / UndefinedBehaviorSanitizer 的 C 测试均通过。仓库也提供跨平台 CI；CI 的配置存在不代表对应远程运行已成功，应检查具体运行结果。

## 8. 行为兼容范围

| 行为 | 移植策略 |
|---|---|
| 轨迹公式、默认圆周方向 | 与原 Python 对照 |
| `ceil` 离散化、控制点直接使用 | 保持 |
| 节点平均、de Boor、导数公式 | 保持 |
| 几何误差定义与 1000 点网格 | 保持 |
| 合法输入时 d 的二分决策 | 保持 |
| 两阶 GL 积分达限 | 增加细分，仍失败则报错 |
| 任意查询参数的链式缓存 | 改为固定节点前缀缓存 |
| Newton 失败后重置二分区间 | 改为持续维护有效包围区间 |
| 负弧长 | 从原来的返回起点改为报非法输入 |
| 搜索未达目标仍返回最后候选 | 改为明确返回未收敛 |

因此这是有数值验证的 C 移植及边界修复，不承诺与原代码在错误输入和未收敛路径上有相同返回行为。
